# Review Round 2 - Fixes & Dispositions

## 1. The Bug

In `dashboard/app.js`, four helper functions (`categoryRisk`, `weeklyActionFor`, `exitActionFor`, and `actionFor`) used the regular expression `/dex|yield|farm|liq/` to match liquidity-focused protocol categories.

Because the regex pattern included `liq`, it inadvertently matched protocols in the "Liquid Staking" and "Liquid Restaking" categories (41 protocols on the board) before the subsequent `/stak/` classification rule could execute. Consequently, the dashboard UI detail modal rendered LP-farming copy (such as *"impermanent loss and pool slippage"* or *"rebalance LP price bounds"*) while `board.json` generated by `lib/model.ts` (which tests `.includes('liquidity')` and `.includes('stak')`) correctly generated validator-slashing copy (such as *"validator slashing and unbonding delay"*).

By updating `/dex|yield|farm|liq/` to `/dex|yield|farm|liquidit/`, liquidity protocols are matched identically to `lib/model.ts`, allowing "Liquid Staking" and "Liquid Restaking" protocols to fall through to the `/stak/` handlers.

  - **After:**  `    if (/dex|yield|farm|liquidit/.test(c)) return 'remove pool liquidity, burn LP shares and claim all trading fee yields';`

- **Line 138 (`actionFor`)**
  - **Before:** `    if (/dex|yield|farm|liq/.test(c)) return 'Deposit $' + cap + ' of liquidity into ' + n + "\x27s core pool on " + ch + ' and maintain active LP range.';`
  - **After:**  `    if (/dex|yield|farm|liquidit/.test(c)) return 'Deposit $' + cap + ' of liquidity into ' + n + "\x27s core pool on " + ch + ' and maintain active LP range.';`

No other line or file in the repository was modified.
